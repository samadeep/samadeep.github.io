## Odd Inversion (ARC231 E): count a parity without counting it

**Problem:** A is non-decreasing. Count sequences B with 1 ≤ B<sub>i</sub> ≤ A<sub>i</sub> whose inversion count is odd, modulo 998244353. N ≤ 2 × 10<sup>5</sup>, A<sub>i</sub> ≤ 10<sup>9</sup>.

**Small case:** A = (2, 2, 3) gives 12 sequences, and only (1, 2, 1), (2, 1, 2) and (2, 1, 3) are odd. Before opening anything: why isn't it 6, and what would make the count easy?

<p class="try">Try it on the judge: <a href="https://atcoder.jp/contests/arc231/tasks/arc231_e">ARC231 E</a></p>

<details class="step" data-kind="hint">
<summary>Hint 1</summary>

Don't count odd sequences. Count **even minus odd**, then odd = (total − difference) / 2. Look for a reason most sequences add nothing to the difference.

</details>

<details class="step" data-kind="hint">
<summary>Hint 2</summary>

Look only at the last two positions. When does swapping B<sub>n−1</sub> and B<sub>n</sub> flip the parity *and* keep B valid?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

If B<sub>n−1</sub> ≠ B<sub>n</sub> and both are at most A<sub>n−1</sub>, swap them:

- **The inversion count changes by exactly 1.** Only the pair (n−1, n) changes order. Every other element still sees both values.
- **The result is still valid**, because A is non-decreasing: both values are ≤ A<sub>n−1</sub> ≤ A<sub>n</sub>.
- **Swapping twice gives back the original**, so these sequences split cleanly into pairs of opposite parity.

```fig title="Figure 1: For A = (2, 2, 3), 4 sequences cancel in pairs; the 8 left over give even − odd = 6"
layout stack
panel "Cancel: last two differ and both ≤ A[2], so swap them"
row
a1: allow "(1,1,2)\neven"
a2: deny "(1,2,1)\nodd"
b1: deny "(2,1,2)\nodd"
b2: allow "(2,2,1)\neven"
a1 <-> a2 "swap"
b1 <-> b2 "swap"
panel "Survive: last two equal (removing them keeps parity)"
row
c1: allow "(1,1,1)\neven"
c2: allow "(1,2,2)\neven"
c3: allow "(2,1,1)\neven"
c4: allow "(2,2,2)\neven"
panel "Survive: B[3] = 3 > A[2], bigger than everything before it"
row
d1: allow "(1,1,3)\neven"
d2: allow "(1,2,3)\neven"
d3: deny "(2,1,3)\nodd"
d4: allow "(2,2,3)\neven"
```

The pairs add +1 and −1 and vanish. The 8 survivors give 7 − 1 = 6, so odd = (12 − 6) / 2 = **3**.

This tool is a **sign-reversing involution**: a map that pairs objects (applying it twice gives the original) and gives each pair opposite signs. The signed total then equals the signed total of the objects it leaves alone.

</details>

<details class="step" data-kind="idea">
<summary>From the idea to a recurrence</summary>

```fig title="Figure 2: Only two cases at the last position survive the cancellation, and each one shrinks the problem"
row
q: main "Last two values\nB[n-1], B[n]" span 3
row
s1: allow "B[n] > A[n-1]" body "bigger than every earlier value,\nso it adds 0 inversions\n(A[n] - A[n-1]) · X[n-1]"
s2: allow "B[n-1] = B[n] ≤ A[n-1]" body "any element sees both copies,\nso it adds an even number\nA[n-1] · X[n-2]"
s3: deny "different, both ≤ A[n-1]" body "swap them: parity flips,\npairs cancel\ncontributes 0"
q -> s1
q -> s2
q -> s3
```

- **B<sub>n</sub> > A<sub>n−1</sub>:** every earlier B<sub>j</sub> ≤ A<sub>j</sub> ≤ A<sub>n−1</sub> < B<sub>n</sub>, so the last element adds no inversions. There are A<sub>n</sub> − A<sub>n−1</sub> such values, times X<sub>n−1</sub>.
- **B<sub>n−1</sub> = B<sub>n</sub>:** any other element is bigger than both copies, smaller than both, or equal to both, so it adds 0 or 2. There are A<sub>n−1</sub> shared values, times X<sub>n−2</sub>.

So X<sub>i</sub> = (A<sub>i</sub> − A<sub>i−1</sub>)·X<sub>i−1</sub> + A<sub>i−1</sub>·X<sub>i−2</sub>, with X<sub>0</sub> = 1 and X<sub>1</sub> = A<sub>1</sub>.

```fig title="Figure 3: X for A = (2, 2, 3) is 1, 2, 2, 6, so odd = (12 − 6) / 2 = 3"
row
x0: box "X0 = 1" body "empty"
x1: box "X1 = 2" body "A1"
x2: box "X2 = 2" body "(2-2)·2 + 2·1"
x3: main "X3 = 6" body "(3-2)·2 + 2·2"
x0 -> x1
x1 -> x2
x2 -> x3
```

In X<sub>3</sub>, the term 1 · X<sub>2</sub> = 2 is the bottom row of Figure 1 (three even, one odd), and 2 · X<sub>1</sub> = 4 is its middle row (four even).

</details>

<details class="step" data-kind="check">
<summary>Code, checks and timing</summary>

Reduce A<sub>i</sub> modulo the prime before multiplying, because A<sub>i</sub> − A<sub>i−1</sub> can be close to 10<sup>9</sup>:

```cpp
ll solve(const vector<ll>& A) {
  ll total = 1;
  for (ll a : A) total = total * (a % MOD) % MOD;
  ll x2 = 1, x1 = A[0] % MOD;  // X_{i-2}, X_{i-1}
  for (size_t i = 1; i < A.size(); i++) {
    ll x = ((A[i] - A[i - 1]) % MOD * x1 + A[i - 1] % MOD * x2) % MOD;
    x2 = x1; x1 = x;
  }
  return (total - x1 + MOD) % MOD * power(2, MOD - 2) % MOD;
}
```

The full [`odd_inversion.cpp`](/labs/cp-weekly-arc231-abc478/odd_inversion.cpp) on the official samples, 5,000 random cases against brute force, and the largest allowed input:

```zsh
$ g++ -O2 -std=c++17 -o odd_inversion odd_inversion.cpp
$ ./odd_inversion < sample.txt
1
3
610589585
$ ./odd_inversion stress 5000
stress: 5000 random cases (N <= 7, A_i <= 5), all match brute force
$ ./odd_inversion bench
bench: T=2, N=200000 each, A_i up to 1e9: 4.13 ms (checksum 468184698)
```

**O(N) time, O(1) extra memory.** Mistakes to avoid:

- **The cancellation needs A to be non-decreasing,** both to keep the swap valid and to make B<sub>n</sub> > A<sub>n−1</sub> mean "bigger than everything before".
- **X can be negative.** In modular code, add `MOD` before halving.
- **An involution must pick the same spot for both partners.** "Swap the first descent" fails: after the swap, that spot is no longer a descent, so the partner picks a different spot.

Watch every pair cancel, then stress-test the recurrence, in your browser:

<div data-lab="py" data-src="/labs/cp-weekly-arc231-abc478/cancel.py" data-args="--show 2 2 3" data-presets="--show 2 2 3|--show 2 3|--show 1 3 3 4|--stress"></div>

> **Insight:** When a problem asks for a parity count, compute the signed sum. Any sign-flipping move you can undo deletes its pairs, and the leftovers usually look like the same problem one or two sizes smaller.

</details>

## Min-First Search (ABC478 F): which trees give this visit order?

**Problem:** start from vertex 1 with a min-heap, always pop the smallest discovered vertex and push its unvisited neighbours. Given the visit order Q, count the trees that produce it. N ≤ 2 × 10<sup>5</sup>.

**Small case:** Q = (1, 3, 4, 2, 5) has 8 trees. Before opening: which vertices could be the parent of 5? Of 2?

<p class="try">Try it on the judge: <a href="https://atcoder.jp/contests/abc478/tasks/abc478_f">ABC478 F</a></p>

<details class="step" data-kind="hint">
<summary>Hint</summary>

A vertex enters the heap the moment its parent is popped. If something bigger than it is popped later, what does that say about when it entered?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 4: Each vertex's parent lies in a window that starts at its previous greater element, so the count is 1 · 2 · 1 · 4 = 8"
row
v3: box "3" body "prev greater: none\nparent in {1}\n× 1"
v4: box "4" body "prev greater: none\nparent in {1, 3}\n× 2"
v2: box "2" body "prev greater: 4\nparent in {4}\n× 1"
v5: box "5" body "prev greater: none\nparent in {1,3,4,2}\n× 4"
row
r: main "1 · 2 · 1 · 4 = 8 trees" span 4
v3 -> r
v4 -> r
v2 -> r
v5 -> r
```

Let g be the last value before Q<sub>i</sub> that is bigger than it. If Q<sub>i</sub>'s parent were popped before g, then Q<sub>i</sub> would be in the heap when g was popped, and since Q<sub>i</sub> < g it would have been popped first. So the parent lies between g and the position just before Q<sub>i</sub>. Any choice there works, and the choices are independent, so **the answer is the product of the window sizes**. The jump loop `p = prev_greater[p]` finds every window in amortized O(N), like a monotonic stack.

</details>

<details class="step" data-kind="check">
<summary>Checks</summary>

```zsh

N=2:      1 trees,    1 orders, formula matches all
```

Every labelled tree up to N = 7 (generated from Prüfer sequences) was run through the min-first search. The formula matched the count for every possible order, and it reproduces samples 2 and 3 (868586527 and 910753763).

> **Insight:** In anything driven by a priority queue, the previous greater element marks the latest moment a smaller item could have entered the queue without being popped too early.

</details>

## Choose Your Role (ARC231 D): pick the side that always wins

**Problem:** N piles of N − 1 stones. First removes 1 to K stones from one pile. Second removes one stone each from 1 to K different piles. Whoever can't move loses. You choose a side and play against the judge.

**Small case:** play N = 3, K = 2 on paper a few times. Which side would you pick, and why does it keep working?

<p class="try">Try it on the judge: <a href="https://atcoder.jp/contests/arc231/tasks/arc231_d">ARC231 D</a></p>

<details class="step" data-kind="hint">
<summary>Hint</summary>

Second wins. Look for an invariant that holds at the start and on the empty board, and that every First move breaks in a way Second can repair.

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

Give pile i one stone of every colour except i. Then "pile i has colour c" exactly when "pile c has colour i", which is a symmetric matrix. When First takes colours c<sub>1</sub>…c<sub>j</sub> from pile i (j ≤ K), Second takes colour i from piles c<sub>1</sub>…c<sub>j</sub>, which is also j ≤ K piles. By symmetry those stones exist, and the matrix is symmetric again.

```fig title="Figure 5: With N = 3, every move by First has a mirror move by Second that restores the symmetry"
layout stack
panel "Start: symmetric"
row
p1: box "pile 1" body "{2, 3}"
p2: box "pile 2" body "{1, 3}"
p3: box "pile 3" body "{1, 2}"
panel "First: colours 2, 3 from pile 1"
row
f1: deny "pile 1" body "{ }"
f2: box "pile 2" body "{1, 3}"
f3: box "pile 3" body "{1, 2}"
panel "Second: colour 1 from piles 2, 3"
row
g1: box "pile 1" body "{ }"
g2: allow "pile 2" body "{3}"
g3: allow "pile 3" body "{2}"
```

The game is finite and Second always has a reply, so First runs out of moves first.

</details>

<details class="step" data-kind="check">
<summary>Checks</summary>


> **Insight:** If a game starts and ends in a symmetric position, look for labels that turn each opponent move into one you can copy. The labels live only in your strategy, not in the problem.

</details>

### Sort Subarray (ABC478 C): one window sort

**Problem:** sort exactly one window of K consecutive elements. Can the whole array end up sorted? **Small case:** A = (1, 4, 1, 4, 2, 1, 3, 5, 6), K = 6 is Yes. [Judge](https://atcoder.jp/contests/abc478/tasks/abc478_c)

<details class="step" data-kind="hint">
<summary>Hint</summary>

Sorting a window can't move anything outside it. Which positions must already be correct?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 6: A differs from sorted(A) first at position 2 and last at 7, a span of 6, so one sort with K = 6 fixes it"
row
c1: allow "1"
c2: deny "4"
c3: box "1"
c4: deny "4"
c5: deny "2"
c6: deny "1"
c7: deny "3"
c8: allow "5"
c9: allow "6"
```

Find the first and last positions where A differs from sorted(A). The answer is Yes exactly when **last − first + 1 ≤ K**. Everything outside the window already matches sorted(A), so the window holds exactly the right values, and sorting it finishes the job. K < N, so a window covering the span always fits. The editorial finds both ends in O(N) with a prefix maximum and a suffix minimum, without sorting.

> **Insight:** An operation that can't touch the outside of a window turns "can it be fixed?" into "do the broken positions fit in one window?".

</details>

### Range Set Insertion Query (ABC478 D): distinct values per position

**Problem:** N empty sets and Q operations "add X to every set S<sub>L..R</sub>". Output every set's size. **Small case:** the sample's sizes are 1 2 3 3 3 1 1 1. [Judge](https://atcoder.jp/contests/abc478/tasks/abc478_d)

<details class="step" data-kind="hint">
<summary>Hint</summary>

Sweep positions left to right. For a fixed value, what changes as ranges start and stop?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 7: Value 2 is covered twice at positions 2 to 4 but counts once; only 0 ↔ 1 changes move the answer"
row
p1: allow "pos 1" body "covered 1×\nadds 1"
p2: allow "pos 2" body "covered 2×\nadds 1"
p3: allow "pos 3" body "covered 2×\nadds 1"
p4: allow "pos 4" body "covered 2×\nadds 1"
p5: allow "pos 5" body "covered 1×\nadds 1"
p6: deny "pos 6" body "covered 0×\nadds 0"
```

Turn each operation into "+1 for X at L" and "−1 for X at R + 1". Sweep the positions, keeping a counter per value. **The set size changes only when a counter moves between 0 and 1.** That's O(N + Q).

> **Insight:** "Distinct count under overlapping ranges" is a reference count per value. Only the transitions between 0 and 1 matter.

</details>

### lt and le (ABC478 E): constraints with < and ≤

**Problem:** find A with values in 1..N satisfying Q constraints A<sub>u</sub> ≤ A<sub>v</sub> or A<sub>u</sub> < A<sub>v</sub>, or say No. **Small case:** A<sub>1</sub> ≤ A<sub>2</sub> ≤ A<sub>3</sub> ≤ A<sub>1</sub> and A<sub>1</sub> < A<sub>4</sub>. [Judge](https://atcoder.jp/contests/abc478/tasks/abc478_e)

<details class="step" data-kind="hint">
<summary>Hint</summary>

Draw an edge u → v for every constraint. What does a cycle of ≤ edges force?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 8: A cycle of ≤ forces equal values, so a < inside one is impossible; across components, topological order works"
panel "A1 ≤ A2 ≤ A3 ≤ A1, A1 < A4: Yes"
row
a1: box "A1 = 1"
a2: box "A2 = 1"
a3: box "A3 = 1"
row
a4: allow "A4 = 2" span 3
a1 -> a2 "≤"
a2 -> a3 "≤"
a1 -> a4 "<"
panel "add A2 < A1: No"
row
b1: box "A1"
b2: deny "A2"
b3: box "A3"
row
b4: deny "A2 = A1 and A2 < A1" span 3
b1 -> b2 "≤"
b2 -> b3 "≤"
b2 -> b4 "<"
```

Every cycle lies inside one strongly connected component, and **all values in a component must be equal**. So a strict edge inside a component means No. Otherwise, number the components in topological order and give each vertex its component's number. Every edge goes forward, so both ≤ and < hold, and there are at most N components. That's O(N + Q).

> **Insight:** With mixed strict and non-strict constraints, collapse the non-strict cycles first. What's left is a DAG.

</details>

### Two Dimensional Invader (ARC231 A): a 2D DP that scans one row at a time

**Problem:** start at (0, 0). Monsters appear in order at (X<sub>i</sub>, Y<sub>i</sub>) with 0 ≤ X, Y < 500. A sword strike walks there for the squared distance, and magic costs Z<sub>i</sub> without moving. Minimize the total for N ≤ 2.5 × 10<sup>5</sup>. **Small case:** (0, 4, 28), (2, 9, 11), (4, 5, 26) costs 16 + 11 + 17 = 44. [Judge](https://atcoder.jp/contests/arc231/tasks/arc231_a)

<details class="step" data-kind="hint">
<summary>Hint</summary>

Pay every Z up front, so a strike costs distance² − Z. Then notice that a squared distance is dx² + dy², and the two parts don't have to be paid at the same moment.

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 9: The 17 from (0, 4) to (4, 5) is paid as 1 + 16 at two different times, so each step scans one column or one row, not the 500 × 500 grid"
row
s1: main "strike (0, 4)"
m1: box "pay (5 - 4)² = 1" body "right after the strike:\npush to every row y\nin column 0"
m2: box "pay (4 - 0)² = 16" body "just before the strike:\npull from every column x\nin row 5"
s2: main "strike (4, 5)"
s1 -> m1
m1 -> m2
m2 -> s2
```

Keep dp[x][y]: the best cost where the last strike was in column x and the y-move to row y is already paid. To strike (X, Y), pull: v = min over x of dp[x][Y] + (x − X)² − Z, which is 500 cells. After the strike, push: dp[X][y] = min(dp[X][y], v + (y − Y)²) for every y, another 500. That's O(N · 1000) in total. The answer is ΣZ + min(0, best v).

> **Insight:** A cost that splits into independent coordinates can be paid in pieces at different times. That turns a scan over the whole grid into a row scan plus a column scan.

</details>

### Three Mex (ARC231 B): build sets with three given mex values

**Problem:** build sets X, Y of integers ≤ 2026 with mex(X) = A, mex(Y) = B and mex({x ⊕ y}) = C, or say No (A, B, C ≤ 1000). **Small case:** A = 1, B = 1, C = 0 is No. Why? [Judge](https://atcoder.jp/contests/arc231/tasks/arc231_b)

<details class="step" data-kind="hint">
<summary>Hint</summary>

X must contain 0..A−1 and Y must contain 0..B−1. Their XORs are forced into the result. Then use a high bit to add exactly what you want.

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 10: For A = 2, B = 3, C = 6, the forced small XORs avoid 6 and the 1024 block supplies exactly 0 to 5"
row
z1: allow "small ⊕ small" body "{0,1} ⊕ {0,1,2}\n= {0, 1, 2, 3}, no 6"
z2: allow "1024 ⊕ (1024 + k)" body "= k for k < 6\n= {0, ..., 5}"
z3: box "everything else" body "1024 + something\n≥ 1024"
row
r: main "X = {0, 1, 1024}, Y = {0, 1, 2, 1024..1029}: mex = 6" span 3
z1 -> r
z2 -> r
z3 -> r
```

If some x < A and y < B have x ⊕ y = C, the answer is No: those values are forced. Otherwise take X = {0..A−1, 1024} and Y = {0..B−1, 1024..1024+C−1}. The XORs below 1024 are the forced ones (which avoid C) plus exactly 0..C−1, so the mex is C. Everything stays ≤ 2023.

> **Insight:** In XOR constructions, a bit above everything in play gives you a separate workspace: values there never collide with the small ones.

</details>

### One Sky, Many Stars (ARC231 C): checking testimonies under updates

**Problem:** people stand at x<sub>1</sub> < … < x<sub>N</sub>. Person i says "my nearest star is at distance d<sub>i</sub>": a star sits at x<sub>i</sub> ± d<sub>i</sub>, and none is strictly closer. After each update to one d<sub>i</sub>, say whether the testimonies can all be true (N, Q ≤ 1.5 × 10<sup>5</sup>). **Small case:** x = (2, 4, 8), d = (3, 3, 0) is Yes. Change d<sub>1</sub> to 7 and it's No. [Judge](https://atcoder.jp/contests/arc231/tasks/arc231_c)

<details class="step" data-kind="hint">
<summary>Hint</summary>

Put a star on every candidate point that nobody forbids: such a star never breaks anyone's testimony, so this is the best you can do. Then ask who can actually forbid a candidate.

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 11: With x = (2, 4, 8), d = (3, 3, 0), each person keeps one candidate that no neighbour's open interval covers"
row
p1: box "x = 2, d = 3" body "candidates -1, 5\nforbids (-1, 5)"
p2: box "x = 4, d = 3" body "candidates 1, 7\nforbids (1, 7)"
p3: box "x = 8, d = 0" body "candidate 8\nforbids nothing"
row
c1: allow "-1 kept" body "5 is inside (1, 7)"
c2: allow "7 kept" body "1 is inside (-1, 5)"
c3: allow "8 kept"
p1 -> c1
p2 -> c2
p3 -> c3
```

The testimonies work exactly when every person has a candidate outside everyone's open interval. The editorial proves that **only the two neighbours' intervals can matter**, and the stress test below agrees (3,000 random cases against checking everyone). So an update to d<sub>p</sub> rechecks only persons p − 1, p and p + 1, with a running count of bad persons. That's O(N + Q). With d<sub>1</sub> = 7, person 1 forbids (−5, 9), which covers both of person 2's candidates.

> **Insight:** When a global condition is a conjunction of local ones, find the radius of influence, then keep a count of the violated local checks under updates.

</details>

### Division Point Hull (ABC478 G): area of a hull of N² points

**Problem:** for every pair i < j, take the point dividing P<sub>i</sub>P<sub>j</sub> in ratio p:q. Output the area of their convex hull as a fraction (N ≤ 10<sup>5</sup>, so there are about 5 × 10<sup>9</sup> points). **Small case:** the sample's 4 points give 59/6. [Judge](https://atcoder.jp/contests/abc478/tasks/abc478_g)

<details class="step" data-kind="hint">
<summary>Hint</summary>

Scale by p + q: the points are q·P<sub>i</sub> + p·P<sub>j</sub> with i < j. Split the indices in half. What shape do the pairs that cross the split make?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 12: Pairs that cross the split form a Minkowski sum of two hulls, so each level of the recursion is linear in hull sizes"
row
all: main "pairs i < j over P[l..r)" span 3
row
l: worker "pairs inside left half" body "recurse"
c: allow "pairs across the split" body "q·hull(left) + p·hull(right)\nMinkowski sum"
r: worker "pairs inside right half" body "recurse"
row
h: main "hull of the three results" span 3
all -> l
all -> c
all -> r
l -> h
c -> h
r -> h
```

The pairs across the split form {q·a + p·b}, whose hull is the **Minkowski sum** q·hull(L) + p·hull(R). That merges edges by angle in linear time. Recurse on both halves and hull the union. The editorial shows each hull has O(length) vertices, giving O(N log² N) with integer arithmetic throughout.

> **Insight:** The hull of all pairwise sums is the sum of the hulls. Divide and conquer turns "all pairs i < j" into that shape.

</details>

### Two Unbalanced Subtrees (ARC231 F): the smallest possible root

**Problem:** write 1..2<sup>N</sup>−1 on a perfect binary tree so that each internal vertex equals |sum of its left subtree − sum of its right subtree|, minimizing the root (N ≤ 18). **Small case:** for N = 3 the minimum root is 2. [Judge](https://atcoder.jp/contests/arc231/tasks/arc231_f)

<details class="step" data-kind="hint">
<summary>Hint</summary>

If a vertex holds r = |a − b|, then its subtree sums to r + a + b = 2·max(a, b). What does that do to divisibility as you go up?

</details>

<details class="step" data-kind="idea">
<summary>Key idea</summary>

```fig title="Figure 13: Both 3-vertex subtrees sum to even numbers (12, 14), so the root |12 - 14| is at least 2"
row
r: main "2" body "|12 - 14|" span 4
row
a: box "1" body "subtree sum 12" span 2
b: box "3" body "subtree sum 14" span 2
row
l1: box "5"
l2: box "6"
l3: box "4"
l4: box "7"
r -> a
r -> b
a -> l1
a -> l2
b -> l3
b -> l4
```

By induction, a subtree with 2<sup>k</sup> − 1 vertices sums to a multiple of 2<sup>k−1</sup>, since 2·max(a, b) doubles the factor its children carry. The root's two subtrees are both multiples of 2<sup>N−2</sup>, and their difference can't be 0, so **root ≥ 2<sup>N−2</sup>**. The editorial builds a tree reaching that bound by recursion. That construction wasn't reimplemented here. A direct search found the bound reached for N = 4 (root 4), shown below.

> **Insight:** For "minimize the root" problems, look for an invariant that every subtree must satisfy. Its strength at the top is your lower bound, and the construction only has to meet it.

</details>
